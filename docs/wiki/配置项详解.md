# 配置项详解

所有配置通过环境变量（或 `.env` 文件）提供。
启动时 `server.py --check` 会做全量校验，违例即退出（fail-fast）。

---

## 密钥（必填）

| 变量 | 说明 |
|---|---|
| `AGNES_TOKEN` | Agnes AI 的 API 密钥，缺失即启动失败 |
| `MCPACCESS_TOKEN` | 客户端访问本服务的 Bearer 密码，自己定一个强随机串 |

生成强随机串：

```bash
openssl rand -hex 32
```

---

## 基础

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8000` | HTTP 监听端口 |
| `IMAGE_DIR` | `/var/lib/mcp-imagegen/images` | 转存图片的落盘目录 |
| `VIDEO_DIR` | `/var/lib/mcp-imagegen/videos` | 转存视频的落盘目录 |
| `AGNES_BASE_URL` | `https://api.agnes-ai.cn` | 上游 API 地址 |
| `AGNES_IMAGE_MODEL` | 空 = 内置默认 | 自定义生图模型 ID |
| `AGNES_VIDEO_MODEL` | 空 = 内置默认 | 自定义生视频模型 ID |

> **模型可自定义**：上游出新模型或更名时，改这两项即可，不用改代码。
> 内置默认：`agnes-image-2.5-flash` / `agnes-video-2.5-flash`

---

## 并发与排队

| 变量 | 默认值 | 说明 |
|---|---|---|
| `MAXCONCURRENCY` | `3` | 同时处理的最大请求数（槽池大小）|
| `QUEUEWAIT_SEC` | `30` | 排队等待上限，超时返回 `busy` |

**设计说明**：不是无限排队。超过并发数的请求进队列，等 30 秒还轮不到就
直接返回 `busy`，让客户端稍后再试。避免请求堆积拖垮服务。

---

## 超时预算（核心设计）

这一组变量构成**嵌套不等式**，启动时自检：

```
客户端 read ≤ 单次分档 ≤ 总预算(200s) < Agent建议(210s) < 优雅停机(220s)
```

| 变量 | 默认值 | 说明 |
|---|---|---|
| `TOTALBUDGETSEC` | `200` | 单请求总预算（秒）|
| `TIMEOUTSCHNELL` | `30` | 生图快速档 |
| `TIMEOUTKOLORSSMALL` | `60` | 生图标准档 |
| `TIMEOUTKOLORS_LARGE` | `120` | 生图大图档 |
| `PERSIST_TIMEOUT_IMAGE_SEC` | `30` | 转存图片的超时 |
| `PERSIST_TIMEOUT_VIDEO_SEC` | `120` | 转存视频的超时 |

**为什么这么设计**：任何一层的超时都必须小于上层，否则会出现
"内层还在等、外层已经放弃"的资源泄漏。启动时校验这套关系，改错了直接报错。

---

## 熔断

| 变量 | 默认值 | 说明 |
|---|---|---|
| `CIRCUITHARDSEC` | `600` | 硬熔断持续时间（秒），触发条件：上游 429/402 |
| `CIRCUITSOFTSEC` | `300` | 软熔断持续时间（秒），触发条件：连续失败 2 次 |

**硬熔断 vs 软熔断**：
- **硬**：上游明确说"你被限流了"（429）或"配额用完"（402），此时再请求也是浪费，直接快失败
- **软**：连接失败、超时等连续出现，疑似上游异常，进入观察期

熔断期间的新请求**立即返回**（不浪费上游配额），熔断结束进入半开状态放一个探针请求试探。

熔断是内存态，重启即清零。

## HTTP 连接层

| 变量 | 默认值 | 说明 |
|---|---|---|
| `HTTPXKEEPALIVESEC` | `25` | 连接保活 |
| `HTTPXCONNECTSEC` | `5` | TCP 连接建立超时 |
| `HTTPXWRITESEC` | `5` | 请求写入超时 |
| `HTTPXPOOLSEC` | `5` | 连接池获取超时 |
| `HTTPXMAXCONNECTIONS` | `10` | 连接池总大小 |
| `HTTPXMAXKEEPALIVECONNECTIONS` | `4` | 保活连接数 |

一般不用改。

## 视频相关（V2）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `TIMEOUT_AGNES_IMAGE_SEC` | `60` | 生图 read 档上限 |
| `VIDEO_SUBMIT_TIMEOUT_SEC` | `30` | 视频任务提交超时 |
| `VIDEO_POLL_INTERVAL_SEC` | `2` | 任务状态轮询间隔 |
| `VIDEO_QUERY_TIMEOUT_SEC` | `10` | 单次查询超时 |
| `TASK_TTL_SEC` | `7200` | 任务表存活时间（2 小时）|
| `TASK_MAX` | `100` | 任务表最大条目数 |

## 校验规则

启动时会检查这组不等式（任一违例即拒绝启动）：

```
单次分档(60s) ≤ 总预算(200s) < Agent建议(210s) < 优雅停机(220s)
队列等待(30s) ≤ 总预算
persist 超时(图30s/视频120s) ≤ 总预算
```

**改配置的思路**：想让某个环节更宽松，必须同时保证上层预算也够，
否则启动就会被拦下——这比运行到一半发现超时好排查得多。
